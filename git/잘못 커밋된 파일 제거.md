# Git: 초기 커밋에서 로그 파일 제거 + 새 원격 저장소로 교체

## 상황
- `backend/hs_err_pid*.log`(JVM 크래시 로그), `backend/replay_pid*.log`(JIT 리플레이 로그)가 initial commit에 포함됨
- 기존 원격 저장소가 삭제되어 새 저장소를 만들어 연결해야 함

## 1. 초기 커밋에서 로그 파일 완전 제거 (히스토리 재작성)

### 준비
```bash
git branch backup-before-rebase   # 복구용 백업 브랜치
git reset                         # 스테이지 초기화 (파일은 유지)
git status                        # 깨끗한지 확인
```
> 스테이지에 변경이 있으면 rebase가 시작되지 않음

### rebase
```bash
git rebase -i --root
```
- 맨 위 `initial commit` 줄의 `pick` → `edit` 으로 변경 후 저장
- 나머지 커밋은 `pick` 유지

### initial commit에서 제거
```bash
git rm --cached backend/hs_err_pid*.log backend/replay_pid*.log
git commit --amend --no-edit
git rebase --continue
```

### 확인
```bash
git ls-files | grep -E "\.log$"   # 아무것도 안 나오면 성공
git log --stat --oneline
```

### 재발 방지
```bash
echo "*.log" >> backend/.gitignore
git add backend/.gitignore
git commit -m "chore: *.log ignore 추가"
```

### 대안 (한 줄로 전체 히스토리에서 제거)
```bash
git filter-branch --index-filter 'git rm --cached --ignore-unmatch backend/hs_err_pid*.log backend/replay_pid*.log' -- --all
```

## 2. 새 원격 저장소 연결 및 배포

### 순서
1. 위 1번(로그 제거 rebase)을 **먼저 완료**한 뒤 push (로그가 새 저장소 히스토리에 올라가지 않도록)
2. GitHub 등에서 새 저장소 생성 (**README / .gitignore / 라이선스 추가 금지**, 빈 저장소)
3. 원격 주소 교체
   ```bash
   git remote -v
   git remote set-url origin https://github.com/계정/새저장소.git
   # origin이 없으면: git remote add origin 주소
   ```
4. 첫 push (새 원격이므로 force push 불필요)
   ```bash
   git branch -M master
   git push -u origin master
   ```
5. 확인
   ```bash
   git remote -v
   git status   # up to date with 'origin/master'
   git pull     # Already up to date
   ```

### CLI로 한 번에 (GitHub CLI)
```bash
gh repo create 저장소이름 --private --source=. --remote=origin --push
```

## 주의사항
- VS Code가 예전 원격을 계속 pull하면 소스 제어 패널 새로고침
- 삭제된 원격 추적 브랜치 정리: `git fetch --prune`
- 다른 사람/서버가 옛 저장소를 쓰고 있으면 각자 `git remote set-url` 필요
- CI/CD·호스팅 연동 시 연결된 저장소 주소도 새 저장소로 변경
- 이미 기존 원격에 push했던 상태에서 히스토리를 바꿨다면 `git push --force-with-lease` 필요 (새 저장소 첫 push는 불필요)
