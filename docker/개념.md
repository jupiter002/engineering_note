VM구조(좌), Docker구조(우)

전통적인 VM :
	국가내에 특별 시를 여러개 생성해서 독립적인 환경을 만든 것과 유사
	특별 시를 여러 개 만들면 예산 책정의 차원이 달라진다 -> VM은 Hypervisor라는 엔진위에 게스트OS를 구동하기 때문에
	독립적인 환경을 만드는데 특화되어 있지만 비용 절약적이지 못하다.

Docker컨테이너 환경 :
	하나의 특별 시안에 행정 자치구를 여러 개 만든 것과 유사
	특별 시를 여러 개 만들 때보다 독립적이지 않지만 시 단위를 여러 개 만들 때보다 쉽게 움직일 수 있고 비용 절약적임.
	-> Docker는 Host OS위에 도커 이미지들을 장착한 컨테이너 위에서 어플리케이션이
	동작하기 때문에 커널을 공유해 io처리에 대해 성능 향상, 게스트OS의 드라이버, 시스템 기본환경이 존재하지 않기 때문에 자원을 소모할 일이 비교적 적음.

Docker가 행정자치구와 다른점 :
Docker는 OS에 대해서 제약적이지 않다. 윈도우에서 생성한 도커이미지를 리눅스, 맥OS에서 실행이 가능함.

Docker사용 이유 : 여러 프로그램등을 한 서버에서 구동하려면 버전 불일치 등의 오류를 일으키는 일이 빈번함. 해결하기위해 프로그램별로 가상의 격리된 공간으로 분리(컨테이너화).

하나의 도커이미로 여러 컨테이너를 생성할 수 있다. 하지만 한 컨테이너에서 여러 이미지를 등록해서 사용할 수는 없다.
